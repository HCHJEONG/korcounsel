## 초기 진단의 판단과 한계

약칭 3행과 별표 3행은 사건번호 집합·날짜·재판 종류가 일치한 상태에서 표시 차이가 관측됐다. 나머지 6행은 모든 사건번호를 기준으로 하는 재판결과 키가 현재 제목에서 더 넓게 관측된다. 단일 대표번호가 같은 사실만으로 번호 집합을 동일하게 만들거나 추가 번호를 버리지 않는다.

같은 출처 ID는 문서 동일성 확정 근거가 아니다. 현재 source ID·reader·HTML hash와 기존 metadata·HTML hash를 별도로 보존하고 검토 상태를 유지했다. 원래 HTML에는 h2 제목 요소가 없어 같은 h2 추출 함수를 적용한 결과가 빈 문자열이며, 이를 원문 제목 부재로 해석하지 않았다.

이미지 파일명/name과 앞뒤 120자의 공백 제외 문맥을 독립적으로 비교하면 15개 등장 위치에 유일한 현재 대응 후보가 있다. 이 수는 제목·전체 사건번호 검증을 대신하지 않으며 실제 연결을 반영하지 않았다. 일부 행은 provider 상태표식만 있어 본문 파일명 후보가 없고, 494행의 이미지 후보 1곳은 문맥 비교도 통과하지 않았다.

## 증거

`data/legacy-reader-scale-20260911-v1/image-title-failure-review.json`에 12행의 전체 제목, 법원/사건번호/종류/날짜 관측, 기존 gmeta, 현재 provenance, 이미지 파일명·order·문맥·후보를 기록했다. 입력 실패 보고서와 현재 reader map의 checksum도 함께 남겼다.

위 JSON의 `REVIEW_ONLY_NO_LINK_CHANGE`는 초기 진단 시점의 상태이며 보존된 기록을 덮어쓰지 않았다. 이 초기 검토를 자동 연결 승인이나 실제 식별 충돌 해소로 처리하지 않는다.

## 후속 제한 규칙과 읽기 전용 재검증

`backend/src/klegal_gold/documents/image_links.py`에 `image-context-link-2` / `image-title-display-1` 경로를 추가했다. 정확한 제목 일치의 기존 경로와 증거 형식은 `image-context-link-1`로 유지한다. 새 경로는 관측된 세 법원 약칭 쌍만 풀어 비교하고, 제목 말미의 단일 `★`만 표시 차이로 허용한다. 법원 지원·재판부를 제거하거나 다른 약칭을 추측하지 않는다. 현재 공통 정규화 모듈에는 법원 약칭 함수가 없어 이 세 쌍은 이미지 표시 대조에만 한정하며, 재판 종류·사건번호 검사는 기존 `normalize/decision.py` 함수를 재사용한다.

새 경로는 제목 전체를 분해하여 법원, 날짜 표기, 선고/자, 단일 완전 사건번호, 재판 종류 원표기가 모두 일치하는지 확인한다. 날짜는 보조 대조 증거이며 재판결과 키에 추가하지 않는다. 병합·반소 번호가 추가된 5행 및 제주 재판부와 번호 차이가 있는 557행은 계속 `IMAGE_DOCUMENT_IDENTITY_UNCONFIRMED`로 거절한다. source ID만으로 연결하지 않으며 registry와 canonical ID를 변경하지 않는다.

6행의 기존 원문 제목은 h2가 아니라 문서 선두 `<div><strong>제목 [사건명]...</strong>`에 있었다. 이 첫 제목의 대괄호 앞 부분과 기존 파생 제목을 대조하고, 현재 HTML의 유일한 보이는 h2와 현재 manifest 제목도 대조한다. 숨겨진 제목, 누락·중복·불일치 제목 및 현재 HTML hash 불일치는 거절한다. 연결 증거에 규칙 버전, 양쪽 제목 원표기·본문 hash·법원 표기·사건번호·날짜·재판 종류를 남긴다. 과거 이미지 bytes의 동일성은 여전히 미확인이다.

같은 Parquet 12행과 해시를 검증한 현재 manifest·HTML CAS 파일만 읽어 연결 함수를 재실행했다. DB 변경이나 네트워크 취득 없이 정확히 6행의 제목 대조가 통과했다. 이미지 연결의 기존 contId·파일명/name·앞뒤 120자 문맥·유일 대응·중복 사용 금지·등장 순서 조건은 그대로 적용했다.
