### 이름 연결 proof 재검증의 제목 공백 경계

후속 독립 코드리뷰에서 양쪽 제목이 공백을 제외하면 같지만 원 문자열이 다를 때, name-v3 연결 생성은 성공하고 저장 시 proof 재계산은 INVALID_IMAGE_NAME_LINK로 거절되는 경계를 재현했다. title_comparison이 없는 경로에서 보존된 source_title_binding.current_title을 사용하도록 ReaderStore만 수정했다. 새 공백 경계에서는 정확한 source ID·부모 HTML hash·raw title로 등록된 CURRENT_SOURCE reader metadata를 조회하고 실제 manifest의 hash·출처·제목·HTML을 검증한다. 실제 h2/strong 대조와 전체 proof 재계산 동등성도 계속 검사하므로 proof에 임의 제목을 넣어 통과시킬 수 없다.

공백 양방향 2건은 수정 전 실패·수정 후 통과했고, binding 변조 및 h2와 compact-equal이어도 등록 metadata에 없는 raw 제목 2건은 거절했다. 관련 제목/이름 단위·PostgreSQL 회귀 164개와 ruff format/check·mypy가 통과했다. 쓰기 테스트는 별도 korcounsel_test DB의 임시 schema에서만 실행했다.

실제 최신 1,806행의 revision이 최종 coverage와 같음을 READ ONLY로 확인한 뒤, name-v3 proof가 있는 299행/1,186위치를 수정된 검증기로 재확인했다. 오류 0이며 title_comparison 없는 1,133위치(289행)는 h2의 원공백 차이로 새 metadata 확인 분기를 거쳐 모두 통과했다. 나머지 title_comparison 있는 53위치도 통과했다. 기존 proof·reader·이미지 상태를 변경하지 않았으며 이 수정으로 전수 재등록을 실행하지 않았다. 같은 숫자 문자열의 앞자리 0, 지원·재판부, 병합 사건번호, 문맥·유일성·순서의 기존 제한은 유지한다.
