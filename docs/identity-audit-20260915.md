## 다른 ID의 후보와 반복 행

후보 생성은 법원 표시 공백만 제거하고 대표 사건번호를 그대로 비교하며,
기존 `decision-key-1`의 재판 종류 분류를 사용했다. 지원·지역·병합 번호를
임의로 지우지 않았다. 후보 없음은 고유 판례임을 증명하지 않는다.
미해결 625개 관찰도 별도 목록으로 보존했다.

- 다른 ID 후보 300묶음의 기존 HTML은 모두 서로 다르다. 표시 텍스트의
  공백을 제외하면 5묶음이 같다: 대법원 73도1658, 73도2173, 73도2711,
  74모68, 76도2359. 이미지·링크·구조 동일성을 의미하지 않으므로 병합 보류다.
- 동일 ID 반복 68묶음 중 9묶음은 HTML 문자열 hash까지 같다. 나머지는
  원문 표현이 달라 이전 행·보강 이력을 유지한다. 같은 HTML이라도 행의
  나머지 59필드까지 같다고 판정하지 않았다.
- 현재 reader도 있는 다른 ID 후보는 대법원 74도3501, 서울고등법원
  2009누12671·2015노1998, 특허법원 2012허4872의 4묶음이다.
- 선고일이 다른 12묶음은 우선 검토 대상으로 표시했다. 예를 들어 기존
  2001나60578의 두 행은 metadata상 모두 판결이지만 과거 원문 조사에서
  판결·중간판결 차이를 관찰했다. metadata만으로 병합하면 안 되는 사례다.

## lawgo 충돌 35개

35개 모두 보존된 scourt 상세 JSON의 `mrgCsNoCtt`가 lawgo 상세의
`사건번호`와 **문자열 그대로 일치**한다. 법원 표시 공백 비교, 재판 종류,
선고일도 일치한다. 병합·본소·반소·참가·부수 사건 표기 34개와
`(울산)2023나11053` 지역 표기 1개가 포함된다.

기존 pipeline은 대표 번호 `csNoLstCtt` 기반 provenance와 lawgo 상세의
전체 번호를 비교했다. 따라서 이번 35개는 전체 번호를 대조하지 않아 생긴
충돌로 설명할 근거가 확보됐다. **감사 판정은 FULL_METADATA_AGREEMENT,
현재 운영 상태는 여전히 CONFLICT**다. 전체 본문 동일성 확정이나 사람의
승인, 법령 버전 확인으로 바꾸지 않았다.

다음 교정 단계는 상세 원본의 병합 번호를 별도 provenance로 계승하고,
원표기·근거를 보존하는 비교 규칙의 새 버전을 검증한 뒤 명시적인 후속
job으로 reader·60필드를 재발행하는 것이다. 기존 docket parser에서 괄호를
무조건 제거하거나 부분 집합 일치를 허용하는 방식으로 완화하지 않는다.
이번 검토에서는 운영 reader·연결·조문·필드를 재발행하지 않았으므로
기존 기준선 EXACT 329 / CONFLICT 35 / UNMATCHED 69는 유지된다.

## 산출물과 검증

- [재현 도구](../scripts/audit_identity_candidates.py): DB 조회는 READ ONLY,
  보존 snapshot 입력 모드는 DB·외부 네트워크를 사용하지 않는다.
- 최종 보고서:
  `data/identity-audit-20260915/audit-71b2d3a1ab7e07ecdf6b6ffa804c98af032ae703912a0b46e0f1179bcaecd2e7.json`.
  파일명은 보고서 SHA-256이다. script·Parquet·입력 보고서 hash,
  2,333개 blob 검증 결과, 후보별 근거·미해결 목록을 포함한다.
- 첫 DB 관찰을 재사용하는 입력:
  `data/identity-audit-20260915/audit-d79ef3432f485e63a4f2631b7d6432594d5d89c8b0a33a57a6969d443d01bc2c.json`.
  이 최초 보고서는 구형 reader 메타데이터 보완 전이며 sentinel을 ID에
  포함한 잠정치다. 최신 집계에는 사용하지 않고 입력 blob 목록만 재사용한다.
- 중간 보고서는 이력으로 보존하며 최신 결과는 위 최종 파일을 따른다.
- 원문·Parquet·DB 연결을 수정하지 않았다. UI·AWS·신규 기간 수집 변경은 없다.
- 검증: 보고서·script hash, 현재 reader 참조 2,260개, 제목 근거 범위
  8,526개, lawgo 35개 비교와 반복 행 집계의 정합성을 확인했다.
  새 도구 ruff check/format, backend mypy 75파일, 기존 lawgo 단위 테스트
  16개가 통과했다. 루트에서 새 script만 mypy로 실행한 명령은 외부 모듈
  타입 stub 부재로 실패했으며 script 전체 정적 타입 검증 통과로 보고하지
  않는다. 앱 코드는 변경하지 않았고 전체 회귀·브라우저·live API는 재실행하지 않았다.

재현 명령은 저장소 루트에서 다음과 같다.

```bash
backend/.venv/bin/python scripts/audit_identity_candidates.py --saved-audit data/identity-audit-20260915/audit-d79ef3432f485e63a4f2631b7d6432594d5d89c8b0a33a57a6969d443d01bc2c.json
```

후속 잔여: 300묶음과 재수집 차이 88쌍의 개별 판단, 미해결 metadata 보완,
번호 변경 3쌍의 공식 대체/문서 전체 확인, lawgo 35개의 규칙 교정·새 revision
발행, 그 이후 근거 있는 canonical 등록이다. 이 감사만으로 전체 동일성
정비 완료라고 보고하지 않는다.
