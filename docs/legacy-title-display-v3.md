# 제목 표시 대조 v3 — wave 1~19 실제 관찰에 한정

`image-title-display-3`는 보존된 두 출처 제목의 표시 차이를 대조하는 규칙이다. 재판결과 키·canonical ID·현재 소송상태를 생성하거나 변경하지 않는다. 기존의 정확한 제목 경로 `image-context-link-1`과 제목 표시 대조 연결 경로 `image-context-link-2`는 유지한다. 별도 이름 표시 변경은 [image-context-link-3](legacy-image-name-display-v1.md)로 기록한다. 이번 변경은 코드와 테스트 준비이며 실제 reader 재적재·worker 재시작·추가 취득을 포함하지 않는다.

## 말미 표식과 제공자 부가표기

기존 단일 `★` 표식 허용을 유지한다. 관찰된 ASCII `*`는 판결·결정 뒤의 단일 말미 표식으로만 허용한다. 결정 근거는 wave 5의 14206행 `2005스26 결정 *`이며, 판결 근거에는 5039·8924·17193·17822·18837·19402·21153행이 있다. 이 표식의 의미를 추론하지 않는다.

판결 뒤 제공자 부가표기는 아래 일곱 **원표기**에 한정한다. ASCII 콜론 뒤 공백 한 칸과 전각 콜론도 원문대로 보존한다.

| 원표기 | 근거 |
| --- | --- |
| `：상고` | wave 6 / 18658, 19935 |
| `：확정` | wave 6 / 18704 등 7행 |
| `：상고기각·확정` | wave 6 / 18810, 19187 |
| `: 확정` | wave 6 / 21237 |
| `: 상고` | wave 6 / 21249 |
| `: 상고기각` | wave 7 / 21474, 22035 |
| `: 항소` | wave 14 / 45992 |

결정 뒤 suffix, 미관찰 콜론·문자 조합, 다른 문구, 별표와 suffix가 동시에 붙은 제목으로 일반화하지 않는다. 두 제목의 비교에서는 부가표기를 별도로 다루지만 원본·증거에서는 제거하지 않는다.

## 유지하는 연결 조건과 새 증거

source ID, 법원 전체 표기, 날짜 문자열, 선고/자, 완전한 단일 사건번호, 재판 종류 원표기가 모두 대조되어야 한다. 기존 선두의 보이는 strong 제목과 현재 유일한 보이는 h2 제목을 각각 해당 제목 문자열에 연결하고 현재 HTML hash도 검증한다. 추가 사건번호·역할표기·분리번호·누락 지원·재판 종류 차이를 표시 차이로 흡수하지 않는다.

이미지의 기존 contId·파일명/name·앞뒤 120자 문맥·유일성·중복 사용 금지·등장 순서는 그대로 검사한다. 제목 대조 통과는 이미지 실물 취득이나 문맥 대응 성공을 의미하지 않는다. 합성 테스트에서 만든 문맥은 실제 판례의 이미지 연결 결과로 세지 않는다.

기존 제목/헤더/본문 hash 증거에 다음을 더한다.

- 양쪽 원 제목의 SHA-256 및 제목 필드별 원문 span.
- `legacy/current_terminal_star`와 해당 span.
- `legacy/current_provider_display_suffix`와 해당 span.
- suffix의 콜론 Unicode codepoint 및 제공자 표시일 뿐이라는 명시적 scope.

span은 해당 원 제목의 Python Unicode codepoint `[start,end)`이며 `title[start:end] == text`를 검증한다. 공백 제거로 비교한 필드에도 원 문자열의 공백·구두점을 되살려 기록한다. 기존 원본문을 덮어쓰지 않는다.

## 거절 근거와 범위

wave 7의 21969행 `결정↔심결`, wave 8의 26948행 `2018노723-1(분리) 판결(주1)`, 27874행의 분리·병합 번호와 초기 추가 번호/지원 차이는 계속 거절한다. wave 9~13에서 추가한 약칭도 별도 재판부를 생략하지 않는다. 31199행의 전주재판부↔(전주), 31285행의 제주 누락, 37988행의 전주 누락, 42193행의 창원 누락·추가 번호, 38854행의 분리번호는 계속 거절한다. 제주지법 본원 쌍은 광주고법(제주)와 별개다.

원 감사는 [기존 제목 검토](legacy-reader-title-review.md) 및 `data/legacy-reader-scale-20260911-v1/image-title-wave{2,4,5,6,7,8}-review.json`에 있다. wave 3은 별도 경로 `data/image-title-wave3-review.json`이다. wave 8 최종 JSON SHA-256은 `3ac2378879e667c570a9e68a81b0a3709c5272c0aa608c9f8123aab51a09e230`다. 기존 감사 파일과 문서는 수정하지 않았다.

## 추가 관찰의 독립 확인

wave 9~13 신규 8쌍은 감사 JSON만 읽지 않고 실제 CAS의 기존 HTML·현재 reader manifest·현재 HTML 각각의 SHA-256을 다시 검증했다. 두 원 헤더, source ID, 제목 필드와 기존 이미지 연결 함수를 대조하여 28개 위치의 문맥 대응 후보를 재현했다. 서울서부지법 39519행은 order 1·2만 대응하고 order 0은 계속 미연결이다. 이는 파일의 읽기 전용 대조이며 실제 reader revision을 생성하거나 corpus DB를 변경한 결과가 아니다.

wave 14의 45992행은 역사적 서울지방법원과 서울지법이 대응하며 서울중앙지방법원으로 바꾸지 않는다. 실제 source 1996735·92가합19434·1996.9.12.·판결과 양쪽 원 헤더·order 0 문맥이 일치한다. 현재 제목에만 붙은 `: 항소`는 원 span `[34,38)`과 ASCII 콜론 codepoint 58을 보존하며 현행 소송상태로 해석하지 않는다. 전각 `：항소`, 공백 없는 `:항소`, 다른 문구는 허용하지 않는다. 50177행의 `제3부판결`은 별도 종류 표현 검토 대상으로 계속 거절한다.

wave 15~19 감사가 완료됐으며 추가 단순 약칭·부가표기는 허용 목록에 더하지 않았다. wave 17~18의 제4민사부·제12민사부·제2민사부·제1민사부·제5민사부·제6민사부 판결 표기는 기존 제목에 없어 보류한다. 부 표시와 함께 관찰된 `: 권리상고`도 이번 규칙에 추가하지 않는다.

전체 19 wave의 제목 실패 174행은 실제 CAS 기존 HTML·현재 reader·현재 HTML을 최종 코드로 다시 검증했다. 표시 후보 60행과 보류 114행을 독립 재현했다. `data/legacy-reader-scale-20260911-v1/image-title-review-all-waves.json`의 SHA-256은 `f4af3d47510ad3cf6def2a3d5ecf0196a2ce9be18ec3866d9aaa5775887e80d6`이며 검증한 image_links.py SHA-256은 `9570e713b2a3e4dbcbf9843e76fca784ede52b1ac6743aafc45804147a3023e3`다. 이 60행에 이름 규칙까지 결합하면 52행/176위치가 문맥 대응하며, 나머지 8행은 제목 대조만 해소되고 이미지 위치 연결은 0이다. 취득이나 실제 등록 성공을 뜻하지 않는다.

worker는 기존 계약에 따라 case_full_no의 양끝 공백을 제외한 표시 제목을 전달한다. 원 case_full_no는 Parquet에, 공백·부가표기를 포함한 원 헤더와 전체 HTML은 불변 보존한다. 직접 제목 비교 함수에 전달된 문자열의 hash/span은 그 문자열 자체에 연결된다.

## 검증

관찰된 v3 양성 제목 42건과 지원·번호·종류·부가표기 음성 사례, 이름 변경과 원문 span/헤더 확인, reader·조문·coverage·API 회귀를 포함한 관련 234개 검증의 최종 성공을 확인했다. 첫 관련 실행에서 225개가 통과했으며 새 제목 통합 fixture 9개는 기존 worker의 제목 trim 계약에 맞게 기대값을 교정한 후 해당 모듈 13개가 통과했다. 원 HTML과 원 헤더의 정확한 보존 assertion은 유지했다.

실제 DB 검증은 `127.0.0.1:55432/korcounsel_test`를 assert한 전용 UUID 스키마만 사용했다. backend 전체 ruff check·format check(107개 파일)와 mypy(55개 source files)가 통과했다. 일반 본문 API에서 새 이름 링크가 내부 이미지로 렌더링되고 원 GIF를 제공하며 미연결로 오표시되지 않는 회귀도 포함한다. 실제 corpus DB/job 재적재와 worker 재시작은 구현 검증에서 수행하지 않았으며 운영 적용 결과는 [전수 실행 기록](legacy-reader-scale.md)에서 별도로 관리한다.
